## Obsidian Trading OS Operating Rules

### Source Priority

1. Decisions Log
2. 03_Trading_System
3. Entry Rules / Exit Rules / Risk Management
4. Other approved Trading OS documentation
5. Knowledge Base
6. Research
7. Trade Journal / Reviews

### Change Control

- Never modify an existing trading rule merely because a trade suggests an improvement.
- Research findings remain research until explicitly approved.
- A proposed rule change must pass through Research → Decision → Trading OS documentation.
- Never overwrite historical decisions.
- Preserve previous versions when system rules change.

### Evidence Classification

Every conclusion must be classified as one of:

- Fact
- Observation
- Hypothesis
- Experiment
- Evidence
- Decision
- Recommendation

Never present an unverified hypothesis as evidence.

### Obsidian Structure

Use existing notes and folders before creating new ones.

Do not create duplicate:
- Strategies
- Entry/Exit Rules
- Reviews
- Research templates
- Decision logs
- Dashboard notes

Use `[[WikiLinks]]` to connect existing notes.

# Claude Operating Workflow

## Before Any Change

1. Read the relevant existing Obsidian note(s).
2. Check `[[Decisions Log]]` for conflicting or superseding decisions.
3. Check `[[03_Trading_System]]` before proposing a Trading OS rule change.
4. Check related Research / Trade Reviews when evidence is involved.
5. Do not create duplicate notes, templates, folders, or dashboards.

## When Analyzing a Trade

Follow:

Trade
→ Strategy
→ Setup
→ Market Condition
→ Index
→ Sector
→ Entry Rules
→ Exit Rules
→ Risk Management
→ Post-Trade Review
→ Research
→ Decision

## When Finding a Possible Improvement

Do NOT directly modify the Trading OS.

Use:

Observation
→ Hypothesis
→ Research
→ Experiment
→ Evidence
→ Decision
→ Trading OS update

## Evidence Discipline

Use these classifications:

- Fact
- Observation
- Hypothesis
- Experiment
- Evidence
- Decision
- Recommendation

Never upgrade an observation or hypothesis into evidence without sufficient support.

## Version Control

Current baseline:

- Trading OS v1.1 = Frozen
- Trading OS v2.0 = Development

Any approved change must be recorded before becoming part of the active Trading OS.

## Obsidian Rules

- Reuse existing notes.
- Reuse existing templates.
- Reuse existing folders.
- Prefer `[[WikiLinks]]`.
- Preserve existing note history.
- Never silently overwrite an existing rule.
- Never create duplicate documentation for the same subject.
